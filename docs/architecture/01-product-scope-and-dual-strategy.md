# A 股研究与交易辅助平台 V1：范围冻结与双策略规范

- 文档版本：V1.0-draft
- 阶段：产品范围与策略规则定义
- 系统定位：个人 A 股研究与交易辅助平台
- 首发策略：缠论三买、趋势突破
- 当前明确不做：回测、券商连接、自动下单、订单执行
- 技术参考：go-stock、gotdx、CZSC

> 本文是架构与业务规则文档，不代表已经实现任何代码。策略参数为第一版可配置的初始规则，需通过人工观察、样本记录和策略复盘逐步校准；在本阶段不进行历史回测，也不宣称这些规则已有统计优势。

## 1. 产品定位与边界冻结

### 1.1 产品定位

V1 是个人 A 股选股、择时、买卖辅助和复盘系统。系统为用户提供可解释、可追踪的研究结论，由用户自行作出交易决定并自行完成实际交易。

核心工作流：

**市场观察 → 全市场扫描 → 双策略识别 → 买卖时机辅助 → 候选跟踪 → 每日复盘。**

### 1.2 V1 必须支持

1. A 股普通股票基础股票池及证券状态维护。
2. 行情接入、标准化、历史 K 线存储和数据质量检查。
3. 市场环境、市场宽度和行业强弱观察。
4. 缠论三买策略独立扫描与状态跟踪。
5. 趋势突破策略独立扫描与状态跟踪。
6. 统一候选展示、策略来源区分、信号冲突提示。
7. 买入观察、等待、持有观察、减仓观察、卖出观察、失效等辅助状态。
8. 自选/观察池、提醒和信号变化记录。
9. 市场、个股、策略及手工交易记录复盘。
10. AI 对行情、技术结构和策略规则进行解释、摘要和问答；AI 不得绕过确定性规则直接生成无证据交易结论。

### 1.3 V1 明确不做

- 不做策略回测、历史收益模拟、参数优化或 Walk-Forward。
- 不接券商 API，不自动下单，不自动撤单。
- 不实现订单路由、成交回报和自动资金/持仓账本。
- 不以 CZSC 的 Position 代替用户真实持仓。
- 不建设复杂机器学习预测系统或多 Agent 自主决策系统。
- 不把第三方自然语言选股结果当作全市场完整股票池。

用户可以手工录入自己的买卖记录和持仓信息用于复盘，但这只是研究记录，不构成系统执行交易。

### 1.4 V1 的验收原则

- 每个候选都能回答“为什么入选”。
- 每个信号都有确认时间、来源周期、规则版本和数据版本。
- 未完成 K 线不作为已确认信号依据。
- 数据不足、行情异常和计算失败必须显式标记，不能等同于无信号。
- 同一股票同时命中两个策略时，保留两份策略结论，不互相覆盖。
- 每个买入/卖出观察结论都能展示触发依据、风险位置和失效条件。

## 2. 参考项目的职责划分

| 项目 | V1 采用的能力 | 不赋予的职责 |
|---|---|---|
| go-stock | 研究工作台交互、K 线展示、股票搜索、第三方条件选股入口、资讯与 AI 工具组织方式 | 不作为策略决策权威，不作为交易账本 |
| gotdx | Go 侧通达信协议适配、证券列表、行情快照、K 线和分钟数据接入 | 不作为完整金融数据治理平台，不直接决定股票是否符合策略 |
| CZSC | 缠论结构分析、分型/笔/中枢、多周期信号计算 | 不负责全市场证券主数据、用户持仓、系统最终买卖辅助结论 |

建议采用 Go 作为业务主控，CZSC 通过独立分析进程/服务提供技术分析结果。V1 不急于通过 FFI 将 Rust 核心嵌入 Go。

注意：CZSC 1.0.x 已将缠论核心迁移到 Rust，并通过 Python/PyO3 暴露。具体信号函数的导入名、注册名和参数模板必须在实施前按锁定版本核验，不能直接假定旧版本 Python API 仍适用。

## 3. 公共数据与扫描规则

### 3.1 股票池范围

V1 默认范围：沪市、深市、北交所 A 股普通股票，覆盖主板、创业板、科创板和北交所。

默认排除：
- ETF、LOF、封闭式基金及其他基金；
- 指数、债券、可转债、B 股及非 A 股证券；
- 已退市证券；
- 非普通股证券品种。

ST/*ST、停牌和退市整理等状态应在主数据中保留并标记。默认策略扫描时排除 ST/*ST 和停牌股票，但不能从历史证券主数据中物理删除，以便观察状态变化和历史记录。

股票池主数据由系统自己维护。gotdx 可用于同步证券代码和名称；行业、上市状态、公告、财务披露等需要各自可靠来源补充。东方财富/问财等第三方筛选仅为候选发现入口，不负责决定系统全市场覆盖范围。

### 3.2 行情周期

V1 策略正式使用：
- 日线：市场及个股环境、趋势和突破区间判断；
- 60 分钟：三买主识别、突破确认；
- 30 分钟：短周期择时和回踩确认。

所有周期必须统一证券代码、时区、交易日历、复权口径和 K 线边界。不得把不同数据源、不同复权口径的 OHLCV 直接拼接给 CZSC。

日线、60 分钟和 30 分钟仅使用已完成 K 线产生“确认”状态。盘中未完成 K 线可以用于显示实时观察值，但必须标记为 `FORMING`，不得冒充已确认信号。

### 3.3 数据质量门

每次计算前检查：
- 股票在对应时点是否上市、是否停牌或处于风险状态；
- K 线是否缺失、重复、乱序或时间戳不合理；
- OHLC 关系是否合理，成交量/成交额是否异常；
- 周期边界是否符合 A 股交易时段；
- 复权类型和复权因子版本是否一致；
- 指标和 CZSC 结构所需的历史长度是否足够。

不满足条件时返回 `DATA_INCOMPLETE`、`DATA_STALE` 或 `ANALYSIS_ERROR`，不能简单返回“无信号”。

### 3.4 行情价格口径

研究价格和实际市场价格必须分开：
- 技术分析可使用明确配置的复权 K 线，但一个策略运行中不得混用前复权、后复权和不复权数据。
- 实际观察价、价格区间、涨跌停约束和手工交易记录必须保留真实未复权价格。
- 复权类型、因子版本、数据源和计算时点必须随分析结果保存。

### 3.5 公共市场环境

建立公共市场状态，不直接代替策略自身判断：
- `FAVORABLE`：市场宽度、指数趋势和风险状态较有利；
- `NEUTRAL`：市场信号不一致或缺少明确优势；
- `UNFAVORABLE`：市场整体风险较高或广泛走弱；
- `UNKNOWN`：数据不足，无法可靠判断。

市场状态原则上作为策略过滤和风险提示输入，不应在没有策略依据时简单一票否决所有机会。各策略可以配置在不同市场状态下允许进入的观察级别。

## 4. 统一策略状态与输出契约

### 4.1 信号与策略决策分离

- **Signal**：单个技术条件或结构事实，例如 60 分钟三买辅助信号、日线突破前高。
- **Strategy Decision**：将多个信号、市场环境、价格位置和失效规则组合后形成的策略判断。

CZSC 输出结构证据；Go 策略层根据确定性规则输出策略决策。AI 只解释已产生的证据和决策，不代替规则计算。

### 4.2 统一状态

建议统一状态：

| 状态 | 含义 |
|---|---|
| `WATCHING` | 已进入策略观察范围，核心条件尚未确认 |
| `SETUP_READY` | 策略前置结构/趋势条件已满足，等待触发 |
| `CONFIRMED` | 核心触发条件由已完成 K 线确认 |
| `WAIT_ENTRY` | 信号成立，但当前位置或短周期条件不适宜，继续等待 |
| `BUY_OBSERVATION` | 达到策略定义的买入观察条件，供用户判断 |
| `HOLD_OBSERVATION` | 用户已标记持有或持续跟踪，原策略逻辑仍有效 |
| `REDUCE_OBSERVATION` | 出现风险升高或趋势减弱迹象，需要检查减仓条件 |
| `SELL_OBSERVATION` | 达到策略定义的卖出观察条件 |
| `INVALIDATED` | 关键结构/趋势条件被破坏 |
| `EXPIRED` | 超过有效时间或交易窗口，不再作为当前机会 |
| `DATA_INCOMPLETE` | 数据不足，不能形成可靠判断 |
| `ANALYSIS_ERROR` | 分析服务或规则执行失败 |

注意：`BUY_OBSERVATION` 不是实际买入指令；`SELL_OBSERVATION` 不是实际卖出指令。没有用户手工持仓信息时，系统不得将技术结构状态伪装成真实 `HOLD`。

### 4.3 每条策略决策的必备信息

- 股票代码、名称、市场；
- `strategy_id`、`strategy_version`；
- `as_of`、信号确认时间和信号周期；
- 当前状态及状态变化原因；
- 市场环境及行业环境；
- 触发证据、辅助证据和未满足条件；
- 参考价格区间、关键支撑/压力位；
- 入场观察条件和失效条件；
- 风险提示、有效期；
- 数据来源、复权口径、`data_version`；
- CZSC 版本及信号配置版本（适用时）。

## 5. 策略 A：缠论三买

### 5.1 策略定位

寻找向上结构中，价格有效离开中枢后回调不重新跌回中枢关键区域的三买机会。主周期为 60 分钟；日线提供环境判断；30 分钟提供入场时机辅助。

策略不是简单“扫描到一个 CZSC 三买字符串就建议买入”。必须分别判断结构证据、市场环境、位置和短周期时机。

### 5.2 周期分工

| 周期 | 作用 | 是否要求出现三买 |
|---|---|---|
| 日线 | 判断个股大级别环境、方向和主要压力位置 | 否 |
| 60 分钟 | 主识别中枢离开、回调及三买辅助信号 | 是，主识别周期 |
| 30 分钟 | 判断短周期回调是否结束、是否重新转强 | 否 |

### 5.3 主结构识别

优先复用 CZSC 原生三买辅助信号：
- `cxt_third_buy_V230228`：作为主识别信号候选；根据最近笔序列寻找向上离开结构，检查末笔回调低点与关键高点的关系。
- `cxt_third_bs_V230318`：均线辅助识别第三类买卖点。
- `cxt_third_bs_V230319`：在第三类买卖点辅助识别之外，补充均线形态信息。

规则约束：
1. 60 分钟 `V230228` 命中，才进入本策略的核心三买确认路径。
2. `V230318` 和 `V230319` 是辅助证据，不强制两个都命中，也不允许其中一个单独替代主信号。
3. 辅助信号冲突时保留冲突事实，降低确认等级或转人工复核，不通过简单加总分掩盖冲突。
4. 若当前 CZSC 版本的信号注册名称或参数模板发生变化，实施时以锁定版本实际注册信息为准，并保留版本映射；不得照搬旧版 API 名称。
5. 信号 `其他`、笔数不足、历史数据不足不等于三买失败，应记录为未就绪或数据不足。

### 5.4 日线环境过滤

建议分为三类：
- **有利**：日线趋势结构向上，价格没有明显远离合理趋势区域，行业/市场环境不明显拖累；
- **中性**：日线方向不明确，但未出现显著破坏；可以观察，不直接升级为强机会；
- **不利**：日线趋势明显向下、重要结构破坏或市场风险明显升高；降低优先级，必要时不进入买入观察。

MA20、MA60、均线斜率、相对强弱等可以作为辅助特征，但不应在第一版未经观察验证前设为僵硬的全局硬门槛。

### 5.5 30 分钟入场时机

60 分钟核心三买确认后，再观察 30 分钟：
1. 短周期回调是否已经出现可确认的结束证据；
2. 是否出现底分型确认、向上笔或其他预先定义的转强证据；
3. 是否仍处于 60 分钟三买结构允许的防守区域之上；
4. 当前价格是否已经明显偏离合理观察区间。

30 分钟不要求独立出现三买。若 60 分钟结构成立但 30 分钟仍在下行回调，状态应为 `WAIT_ENTRY`，而不是直接 `BUY_OBSERVATION`。

### 5.6 买入观察条件

只有同时满足以下原则性条件，才可升级为 `BUY_OBSERVATION`：
- 60 分钟主三买辅助信号已由已完成 K 线确认；
- 关键结构位置可明确解释并能计算；
- 30 分钟没有显示回调继续恶化，且存在预先定义的短周期转强证据；
- 日线环境不是明确不利状态，或策略配置允许在该状态下观察；
- 当前价格未明显超出策略可接受的观察区间；
- 数据质量门全部通过。

否则分别保留 `CONFIRMED`、`WAIT_ENTRY` 或 `DATA_INCOMPLETE`。

### 5.7 失效与过期

- 60 分钟价格破坏三买结构防守位，且满足配置的确认方式时，转为 `INVALIDATED`。
- 日线大级别结构明显恶化时，转为风险提示或降低状态。
- 信号超过可配置的有效周期仍未出现入场时机，转为 `EXPIRED`。
- 任何防守位必须来自可追溯的结构数据，例如中枢上沿、回调低点或策略明确定义的关键价位；不允许 AI 随意生成。

第一版有效期先采用可配置项，不预设全市场统一的固定小时数。策略配置必须明确按“已完成 60 分钟 K 线数量”还是按交易日计算。

### 5.8 输出示例（语义示例）

```text
策略：缠论三买
状态：WAIT_ENTRY
日线环境：中性偏有利
60分钟主信号：三买辅助命中，已确认
60分钟辅助证据：V230318 命中；V230319 未确认
30分钟时机：回调尚未出现明确转强证据
参考结构：中枢上沿、末笔回调低点
下一步观察：等待30分钟转强，不追随当前下行回调
失效条件：60分钟收盘确认跌破策略防守位
```

## 6. 策略 B：趋势突破

### 6.1 策略定位

寻找日线趋势已经具备向上条件，价格有效突破一段整理区间或前期关键高点，并获得成交量/成交额等量价特征支持的机会。重点研究趋势启动和趋势延续，不把普通盘中冲高等同于有效突破。

### 6.2 周期分工

| 周期 | 作用 |
|---|---|
| 日线 | 判断趋势、整理区间、关键前高和收盘突破 |
| 60 分钟 | 确认突破后是否站稳、是否快速回落 |
| 30 分钟 | 观察回踩关键位后的短周期转强和入场时机 |

### 6.3 趋势环境条件

日线建立趋势特征：
- MA20、MA60 的相对位置及斜率；
- 收盘价相对均线的位置；
- 近阶段高低点是否呈现抬高；
- 行业相对强弱和市场环境；
- 波动率是否过度扩张。

首版以这些特征形成 `FAVORABLE / NEUTRAL / UNFAVORABLE` 评价，不将某一条均线条件作为未经验证的唯一硬门槛。具体参数通过版本化配置控制。

### 6.4 突破定义

首版采用可配置的前 N 日关键区间突破作为基准规则：
- 参考区间由当前交易日之前已经完成的 N 根日线计算；
- 当前已完成日线收盘价高于该区间上沿，并满足配置的突破缓冲条件，才记为日线突破确认；
- 盘中价格越过区间上沿但日线尚未收盘，只能记为 `WATCHING` 或盘中观察，不得记为正式 `CONFIRMED`；
- 区间长度支持多个配置档位，例如 20、30、55 个交易日，必须记录所用配置；
- 当前 K 线不得参与自身历史区间最高价计算，避免比较口径错误。

### 6.5 量价确认

量价是突破质量证据，而非单纯“放量越大越好”。至少观察：
- 当日成交量相对过去一段时间均量的变化；
- 成交额是否达到该股票的流动性要求；
- 收盘位置是否接近日内高位；
- 突破时是否出现异常巨量、长上影或快速冲高回落；
- 相对行业/市场是否具有强度。

成交量比率、成交额门槛和收盘位置阈值必须作为策略配置版本管理。没有数据时标记缺失，不得自动按通过处理。

### 6.6 突破后确认与入场择时

- 日线收盘突破后，状态进入 `CONFIRMED` 或 `WAIT_ENTRY`。
- 60 分钟观察突破区间上沿附近是否能够站稳，是否出现明显回落到区间内部。
- 30 分钟必须观察真实回踩关键位后的短周期转强；CZSC 标签不能替代回踩事实。
- 若突破后价格短时间大幅远离突破位，转为 `WAIT_ENTRY`，避免系统把追高当作理想时机。
- S4.4 冻结：M60 站稳后，至少一根非最新完整 M30 K 线的 Low 进入突破位容忍区间；最新完整 M30 Close 重新站回突破位上方，且严格高于前一根 M30 High；最新 bar 收盘位置达到显式配置门槛。具体公式、配置字段和失败语义见 [策略规则与决策契约](07-strategy-rules-and-decision-contract.md)。

### 6.7 买入观察条件

原则上需要：
- 日线有效突破已经收盘确认；
- 趋势环境不是明确不利状态；
- 量价证据达到策略配置要求，或明确标记为“突破但量价证据不足”；
- 60 分钟没有出现突破失败；
- 30 分钟已完成 M30 回踩、收复突破位和转强确认；
- 当前价格仍处于可解释的风险收益观察区间；
- 数据质量门全部通过。

### 6.8 突破失败、失效与过期

- 日线收盘重新回到突破区间内部，按策略配置判断为突破失败或降级观察。
- 60 分钟快速跌回区间内，可先标记 `REDUCE_OBSERVATION` 风险提示；是否最终 `INVALIDATED` 由明确的收盘确认规则决定。
- 突破后在有效期内没有形成合理时机，转为 `EXPIRED`。
- 出现明显放量长上影、异常波动或市场风险快速恶化时，提高风险等级，但必须展示具体证据。

### 6.9 输出示例（语义示例）

```text
策略：趋势突破
状态：WAIT_ENTRY
日线趋势：向上
突破区间：前N日关键高点
日线突破：已收盘确认
量价证据：成交额满足门槛；量比达到配置要求
60分钟确认：暂时站在突破位上方
30分钟时机：等待回踩后转强
下一步观察：突破位附近能否形成支撑
失效条件：日线收盘确认回到原整理区间
```

## 7. 双策略汇总与冲突处理

### 7.1 结果不合并，股票可以去重展示

底层保存两条独立策略决策：
- `symbol + strategy_id + signal_instance`；
- 同一股票同时命中两种策略时，候选工作台可以合并显示一张股票卡片，但卡片内保留两套独立状态、证据、价格位和失效条件。

### 7.2 不直接相加分数

三买策略分数和趋势突破策略分数各自具有不同含义，不能直接相加或横向比较。V1 可以先使用策略内部等级（高/中/低）和明确证据，不急于建立跨策略统一总分。

### 7.3 冲突展示

- 三买有效、突破无效：保留三买机会，同时提示突破策略失败事实。
- 突破有效、三买无效：保留突破机会，不因三买未命中否决突破策略。
- 两者均有效：标记“双策略共振”，但不自动提高买入结论；需分别检查两套风险位。
- 两者方向相反或关键结构矛盾：标记“策略冲突”，提示人工复核。

双策略共振是一种研究标签，不代表已证明有更高胜率。

## 8. 观察池、提醒与复盘

### 8.1 观察池分类

- 全市场策略候选；
- 三买候选；
- 趋势突破候选；
- 双策略共振；
- 等待入场；
- 用户自选；
- 用户手工标记持有/已卖出。

候选池保存来源和状态变化历史。策略信号失效不应无痕删除，应保留为历史事件。

### 8.2 提醒

V1 提醒内容包括：
- 新策略信号确认；
- `WAIT_ENTRY` 转为 `BUY_OBSERVATION`；
- 关键防守位被触及或确认破坏；
- 突破失败；
- 信号过期；
- 行情数据缺失或过期。

提醒必须区分“盘中触碰”“未完成 K 线观察”和“收盘确认”。

### 8.3 复盘

复盘分四层：
1. 市场复盘：指数、市场宽度、行业强弱和市场环境变化。
2. 个股复盘：关键 K 线、结构变化、信号形成/失效。
3. 策略复盘：当日各策略新增、维持、失效和过期候选及原因。
4. 个人交易复盘：用户手工录入的实际买卖与系统当时提供的观察结论对照。

V1 复盘以事实、证据、状态变化和人工注释为主，不计算策略历史收益曲线，不得包装成回测。

## 9. V1 日常使用流程

### 盘前
- 更新证券状态、交易日历和公告/财务等必要信息；
- 检查前一交易日数据是否完整；
- 生成市场环境和行业观察；
- 运行日线初筛和策略候选更新。

### 盘中
- 更新实时行情和已完成的 60 分钟/30 分钟 K 线；
- 对候选股刷新策略状态；
- 区分盘中观察与已完成 K 线确认；
- 对关键位触及、突破失败和结构失效发出提醒。

### 收盘后
- 确认日线和分钟线收盘数据；
- 对两套策略重新计算最终收盘状态；
- 生成候选变化和失效清单；
- 生成市场、策略和个股复盘；
- 用户可补充手工交易记录和复盘备注。

## 10. V1 验收清单

### 数据中心
- [ ] 股票池覆盖约定的沪深北 A 股普通股票品种，并能说明排除项。
- [ ] 股票列表同步失败不会清空已有有效股票池。
- [ ] 能区分正常、ST、停牌、退市等状态。
- [ ] 日线、60 分钟、30 分钟时间边界和复权口径一致且可追溯。
- [ ] 未完成 K 线不进入正式确认逻辑。
- [ ] 数据缺失、陈旧、异常和分析失败有独立状态。

### 三买策略
- [ ] 60 分钟主识别逻辑与锁定 CZSC 版本的真实信号注册信息一致。
- [ ] 辅助信号不会替代主信号，也不会被错误地要求全部同时命中。
- [ ] 日线环境、30 分钟时机、结构防守位和失效条件可解释。
- [ ] 信号确认时间不早于所需已完成 K 线可用时间。

### 趋势突破策略
- [ ] 突破区间只使用当前交易日之前已完成的 K 线计算。
- [ ] 盘中越过关键位与日线收盘确认明确区分。
- [ ] 趋势、量价、60 分钟确认和 30 分钟择时证据可追溯。
- [ ] 突破失败和信号过期有明确条件。

### 统一工作台与复盘
- [ ] 同一股票可以保留两套策略独立结果。
- [ ] 双策略共振、策略冲突和单策略命中有清楚的展示方式。
- [ ] 用户手工交易记录与策略建议可以关联，但不自动推断真实持仓。
- [ ] 每日复盘能解释候选新增、状态变化、失效和数据异常。
- [ ] 不包含回测、券商连接和自动交易功能。
