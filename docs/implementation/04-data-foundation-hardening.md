# 第 04 段：D1/D2 基础层审计与数据安全加固

## 本段范围

本段以 codex/d1-d2-foundation 的已有代码为基线，只修复已实现基础层中会造成数据覆盖、序列污染或分析结果不可追溯的问题。不生成策略引擎、Hertz API、扫描调度或自动交易。

## 审计发现与修复

1. **证券基础资料稀疏覆盖**：gotdx 名单只提供证券代码/名称，上市状态等字段可能为 UNKNOWN 或空值。原 upsert 会把已存在的行业、地区、上市状态和日期字段清空。本段将空字段视为“该来源未提供”，并保留已有非空资料；新数据明确提供时才更新。当前没有提供显式清空字段的接口。
2. **交易日历来源优先级未落到仓储层**：领域层已有 IsAuthoritative，原仓储写入没有使用。本段将其接入 upsert：交易所公告优先，其次人工覆盖，再其次 Tushare；低优先级来源不能覆盖高优先级记录。
3. **K 线同序列数据源静默切换**：原主键不包含 source，相同时间点来自另一供应商时会被 upsert 覆盖。本段改为同一证券/周期/复权序列只接受同一来源；来源切换需要单独核对重叠区间并执行显式迁移，本段不提供自动迁移。
4. **分钟线时间边界缺少质量门**：统一模型约定 bar_time 为 K 线结束时间。本段对 M30/M60 校验 D2 约定的结束时刻，无法归入已知结束边界的输入直接拒绝，不擅自推算起始时间或跨午休换算。
5. **CZSC HTTP 契约校验不足**：原客户端只校验 schema、证券和周期。本段增加请求字段、+08:00、严格递增、OHLC/成交量有限值及 5000 根上限检查；响应必须匹配请求的证券、周期、复权、来源、K 线数量和 as_of，并检测超大响应。
6. **CZSC 输出时间偏移**：服务端对 naive 时间附加 +08:00；若意外收到带其他时区的 aware datetime，现在拒绝输出，不静默标注为上海时间。

## 新增测试

- SQLite：稀疏证券资料不清空完整字段、交易日历来源优先级、禁止跨数据源 K 线序列。
- gotdx：拒绝非已知 M30/M60 结束边界。
- Go CZSC 客户端：拒绝错误时区与不匹配的数据源响应。
- Python CZSC 服务：拒绝非上海时区的 aware 输出时间。

## 本段未实现

- Tushare 证券基础资料和交易日历的真实同步客户端。
- 交易所公告解析和日历自动更新。
- gotdx K 线真实供应商样本的最终时间标签/成交量单位验收；当前边界校验是 fail-closed，不代表已经完成真实行情端到端验证。
- go-stock 多源行情回退；其 Wails 应用包耦合未解决，不在本段导入整个应用。
- 缠论三买和趋势突破策略规则、信号状态机、观察池及复盘。
- Hertz API、扫描调度和工作台接口。
- 回测、券商接入、自动下单和订单执行仍明确不做。
