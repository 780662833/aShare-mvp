## 1. 项目定位与冻结边界

aShare-mvp V1 是个人 A 股研究与交易辅助平台，负责把市场数据转换为可追溯的策略观察结论，支持扫描、历史查询与人工研究。

V1 的核心原则：

1. **数据先于信号**：数据质量、来源、复权口径、时间和完整性不满足要求时，必须显式失败或标记数据不完整，不得伪装成有效结论。
2. **PIT（Point-in-Time）**：决策只能使用决策时点已经可获得且已经完成的数据，禁止未来 K 线和未来采集信息污染历史判断。
3. **策略独立**：缠论三买与趋势突破各自维护策略标识、版本、配置、状态、证据和失效条件；不得把两个策略合成一个评分或状态。
4. **可审计、可复现**：保存决策 ID、策略/配置版本、as_of、数据版本、CZSC profile 与原始 payload；历史读取不得重新运行策略。
5. **复用优先、最小核心**：复用 gotdx 与 CZSC 的公开能力；Go 负责数据治理、应用编排和确定性策略规则，不复制第三方协议或缠论算法。
6. **人工负责交易决定**：策略输出是研究观察，不是买卖指令。

明确不属于 V1/S1–S5 交付范围：券商连接、自动下单、订单执行、回测/参数优化、AI 自主交易、组合资金分配、完整研究工作台 UI，以及尚未实施的通用 HTTP 产品 API。

## 3. 当前总体架构

V1 使用 **Go 模块化单体 + 独立 CZSC 分析服务 + SQLite 持久化**。Go 负责业务边界、数据质量门、应用服务、确定性策略与扫描编排；CZSC 服务只负责技术结构/信号分析。

### 3.1 模块职责

| 模块/边界 | 职责 | 不负责 |
|---|---|---|
| `market/universe`、`market/calendar` | 证券身份、每日证券状态、交易日历 | 策略判断 |
| `marketdata` | D1/M60/M30 标准 K 线、时间语义、质量检查 | 生成策略信号 |
| `gotdx` adapter | 通过公开 API 获取证券名单和 K 线 | 补造缺失的上市状态、ST 历史或日历事实 |
| `storage/sqlite` | 领域数据、策略决策、扫描运行和扫描项持久化/查询 | 重算策略 |
| `czscclient` + `czsc-service` | Go/Python HTTP/JSON 契约；CZSC 结构和信号计算 | 写业务表、作最终策略结论 |
| `feature` | 均线、区间高点、量比、收盘位置等可复算通用特征 | 复制 CZSC 缠论算法 |
| `strategy/chan3buy` | 缠论三买规则与决策 | 调用趋势突破策略 |
| `strategy/trendbreakout` | 趋势突破规则与决策 | 调用缠论三买策略 |
| `app/strategy` | 数据预检、CZSC profile 编排、双策略独立执行和保存 | 合并两套决策 |
| `scanner` | 批量调度、记录扫描运行和逐证券结果 | 复制策略规则 |
| 扫描/历史 read model | 根据已保存 ID 读取扫描项与原始策略决策 | 重新运行 CZSC 或策略 |

### 3.2 主数据流

```text
行情源 / 已入库证券资料与交易日历
    -> 标准化 D1 / M60 / M30 K 线
    -> as_of、完整性、来源、复权、时间与新鲜度质量门
    -> CZSC 按周期分析（独立 HTTP/JSON 服务）
    -> Go app/strategy
         -> chan3buy 独立评估 -> 独立决策 -> 独立保存
         -> trend_breakout 独立评估 -> 独立决策 -> 独立保存
    -> scanner 批量调度与扫描结果留痕
    -> 原始 DecisionID 关联的扫描结果读取
    -> strategy_decisions 历史筛选与分页查询
    -> 人工研究、观察和复盘
```

## 4. 核心策略规则与数据契约

### 4.1 双策略隔离

- 两套策略拥有独立 StrategyID、StrategyVersion、ConfigVersion、状态和证据。
- 可以共享标准行情和 CZSC 技术快照，但不得共享/覆盖策略状态。
- 同一证券的两份决策分别持久化；一套策略的等待、数据不完整或执行错误不得回滚另一套成功结果。
- 展示层即使合并股票卡片，也必须保留策略来源和各自证据。

### 4.2 PIT 与数据质量

- `as_of` 是决策信息截止时点；策略只使用已完成且 `BarTime <= as_of`、`FetchedAt <= as_of` 的 K 线。
- Bar 时间采用显式 UTC+08:00，代表 K 线结束时间。
- 同一分析序列必须保持证券、周期、复权和数据来源口径一致。
- 交易日历、证券每日状态、行情和 CZSC 快照必须满足时点一致性。
- 缺失、乱序、重复、未来数据、跨来源/复权混用、快照不匹配等问题必须 fail-closed 或显式 DATA_INCOMPLETE。

### 4.3 缠论三买

- D1 提供趋势环境；M60 是三买主识别周期；M30 只提供短周期择时辅助。
- M60 主三买信号、辅助信号和可追溯防守位必须满足策略契约；主信号生命周期未知或过期时不得正常升级。
- M30 辅助标签不能替代时序、收盘与防守位检查。
- 防守位不可重建时不得猜测价格；失效和超龄按版本化规则处理。

### 4.4 趋势突破

- 突破区间只使用当前交易日之前已完成的 N 根日线；当前日线不得参与自己的区间高点。
- 必须满足日线收盘突破及对应 CZSC 事件信号，并通过趋势/量价过滤。
- M60 负责确认突破位站稳；M30 必须在 M60 站稳后完成真实回踩、收复突破位、转强和收盘位置确认。
- CZSC 短周期标签是附加证据，不能代替真实 M30 价格行为。
- 所有阈值属于显式版本化配置；测试夹具数值不是实盘建议。

详细、规范性规则以 [策略规则与决策契约](architecture/07-strategy-rules-and-decision-contract.md) 为准。

## 5. 持久化与历史查询契约

- `strategy_decisions` 是策略决策的权威持久化记录；S5 复用既有表，不新增 S5 决策表或 migration。
- 决策 ID 幂等；同一 ID 对应不同 payload 时必须冲突，不得静默覆盖。
- 扫描项保存原始 DecisionID；历史读取按该 ID 取回原始完整决策，不重跑策略、不用当前行情重建历史。
- S5 支持 `ts_code`、`strategy_id`、`status`、`from_as_of`、`to_as_of` 过滤；时间边界包含。
- 分页 `limit` 范围为 1–200，`offset` 从 0 开始；排序固定为 `as_of DESC, decision_id DESC`。
- 总数与当前页在同一只读事务中读取，避免统计与页面结果来自不同快照。

1. 数据源在真实交易日返回的 bar 时间、完成状态、成交量量纲和复权口径是否符合契约；
2. 证券每日状态和交易日历数据是否足以支持目标证券与历史日期；
3. 两套策略的状态、证据、失效条件是否容易审阅，是否出现误报/漏报；
4. 扫描结果与历史决策是否能稳定关联、复现和查询；
5. 扫描运行中断、存储失败和 context 取消时，运行状态是否清晰可辨。
